## Teorifrågor
### Vad är agil utveckling, och vad i ert arbetssätt den här veckan var agilt?
- Vi arbetade med mindre delar åt gången, haft diskussioner (möten) med varandra, och hjälpt varandra då vi stött på problem, vi har också använt oss utav GitHub för att för att ha koll på projektet.
### Vilka Scrum-roller och moment använde ni (till exempel Scrum Master, daily, sprint och retrospektiv)? Beskriv hur de fungerade i er grupp.
- Vår scrum-master höll i våra daily standups, ansvarat för sprinttavlan och hjälpte till när problem uppstod. Våra sprintar hade tydliga mål som skulle utföras under en begränsad tid. Vi hade daily standup  där alla medlemmar berättade vad de gör och hur det har gått. Efter sprinten diskuterade vi vad som har fungerat bra och vad som kunde gått bättre. 
### Beskriv hur en user story gick från Att göra till Klart hos er, med branch, Pull Request, review och merge.
- Alla user storys började på "att göra",  där sedan en utvecklare valde sin user story att arbeta med och flyttade den då till "pågår". Då skapade alla som egen branch, gjorde sin ändring i koden, skickade in den till GitHub och skapade en pull request och flyttade sedan på sprinttavlan till "granskning". En annan utvecklare gick sedan in och gjorde en code review och sen godkände den för en merge in i main. Då flyttas kortet på sprinttavlan till "klar".
### Vad är en merge-konflikt, när uppstår den och hur löser man den på GitHub? Ge ett exempel med en funktion i index.html. Om ni fick en konflikt under veckan, beskriv den.
- Vi hade inga konflikter. En merge-konflikt är när två utvecklare gör en ändring på samma rad och git inte vet vilken rad som är den rätta. Om det skulle uppstå går man in på pull request och klickar på resolve conflicts, granskar de markerade raderna och väljer vad som ska behållas och sedan gör en commit på lösningen och slutför mergen.
